# Dependency resolution & module paths

How taupkg turns your `[deps]` into a compiled binary — resolution, the lock
file, integrity, and automatic module-path handling.

---

## Single-version, whole-graph resolution

taupkg resolves the **entire transitive dependency graph** and unifies every
package to **one version**.

This is a deliberate consequence of Tauraro's **unity build**: the compiler links
exactly one copy of each module. Unlike Cargo — which can keep several
semver-major versions of a crate side by side — taupkg must pick a single version
per package. The upside is a simpler, stronger model:

- The resolved graph is exactly what gets compiled.
- Two **compatible** constraints (`^1.0` and `^1.2`) unify automatically to the
  newest matching version.
- An **incompatible** pair is a hard, clearly-reported conflict — never a silent
  duplicate:

```
error: dependency conflict on 'liblog':
    app requires ^1.0  (resolved to 1.4.2)
    libnet requires ^2.0
  Tauraro links one version of each package; align these constraints or pin an
  explicit version.
```

The resolver walks the graph breadth-first, reading each package's own
`taupkg.toml` to discover its dependencies (the transitive step), and always
prefers the highest version satisfying a constraint.

## Path rebasing

A `path` dependency resolves **relative to the manifest that declares it**, not
the top-level project. Consider:

```
workspace/
├── app/          taupkg.toml:  liba = { path = "../libs/liba" }
└── libs/
    ├── liba/     taupkg.toml:  libb = { path = "../libb" }
    └── libb/
```

`liba`'s `../libb` is resolved relative to `liba`'s own directory
(`libs/liba` → `libs/libb`), **not** relative to `app`. Resolved local paths are
stored in the lock as **project-root-relative** paths, so the lock stays portable
across checkouts.

## The lock file

`taupkg.lock` pins the full resolved graph. Commit it.

```toml
[[pkg]]
name       = "liba"
version    = "1.0.0"
constraint = "^1.0"
source     = "github:user/liba@<commit-sha>"
checksum   = "sha256:…"
```

- **Git sources are pinned to the exact commit SHA**, so a moved tag can't change
  what you build.
- **Local paths are project-root-relative** for portability.
- **`checksum`** is a Merkle-style content hash of the whole package tree
  (excluding `.git`, `.taupkg`, `build`, `target`), so any change to the
  installed files is detectable.

### Reproducible / offline installs

| Command | Behaviour |
|---------|-----------|
| `taupkg install` | Resolve, reuse compatible locked versions, write an updated lock |
| `taupkg install --locked` | Replay the lock **exactly**; error if it's missing or stale |
| `taupkg install --offline` | Never touch the network — reuse `.taupkg/packages/` only |
| `taupkg audit` | Re-hash installed packages and verify against the lock |

`--locked` is the CI setting: it guarantees the build uses precisely what the
lock records.

## Automatic module path (`TAURARO_PATH`)

The Tauraro compiler resolves imports from a search path (like Python's
`PYTHONPATH`), overridable via the `TAURARO_PATH` environment variable.

`taupkg build`, `run`, and `test` set `TAURARO_PATH` **automatically** to every
installed package's importable directory (`.taupkg/packages/<name>/src`, or the
package root for flat packages) and compile your project's real `src/main.tr`
**in place**. No sandbox copy, no flags:

```tauraro
from mathlib import add      # resolved via the auto-set TAURARO_PATH
```

Details:

- **Your existing `TAURARO_PATH` is preserved** — taupkg prepends its entries and
  appends whatever you already had, so manual entries keep working.
- **Absolute paths** are used, so resolution is independent of the working dir.
- A dependency's own transitive imports (`from libb import …` inside `liba`)
  resolve because every package's `src/` is on the path.

### Compiling with `tauraroc` directly

Run [`taupkg env`](../README.md#env) to get the path and export it:

```sh
eval "$(taupkg env)"          # POSIX
tauraroc src/main.tr -o app
```

On Windows, `taupkg env` prints a `set TAURARO_PATH=…` line and a PowerShell
`$env:TAURARO_PATH = "…"` line.

### Hermetic fallback

If in-place resolution ever misbehaves, build hermetically:

```sh
taupkg build --sandbox
```

This copies your `src/` and every dependency into `.taupkg/build/` as top-level
directories and compiles there, so resolution is purely by layout.

## Linking

taupkg leaves linking to the compiler, which reads link directives from the
imported bindings themselves:

- FFI packages generated by [`taupkg bindgen`](bindgen.md) carry
  `# tauraro-cpp-*` pragmas — system libraries and C++/C shims link
  automatically, with no manual `-l`.
- For a prebuilt library not covered by a pragma, link it as usual
  (`tauraroc app.tr -l<name>`), or record it in your build.

## Cross-compilation

`taupkg build --target <triple>` cross-compiles with zero extra toolchain setup —
`tauraroc` bundles `zig cc` (clang + lld + libc for every target). Examples:

```sh
taupkg build --target linux-arm64
taupkg build --target windows-x64
taupkg build --target macos-arm64
taupkg build --target wasm-wasi
```
